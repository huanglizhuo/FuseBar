# FuseBar 产品审视与机会地图

日期：2026-09-17。基线：main `b39102d` 的 1.1.0 源码、现有原生界面预览、规划与验证记录。不是重新执行的完整真机验收。`/Applications/FuseBar.app` 的版本元数据仍为 1.0.1，不能把源码能力全部算作当前安装包能力。本文件是建议，未替代已接受的 PLAN，也未授权以下所有功能进入实现。

## 推荐定位

**FuseBar：从一个入口，看清状态，切换应用，继续手头的事。**

核心价值应当是减少日常操作在菜单栏、Dock、Finder、设置之间的往返。保留小圆环这个强识别资产，让展开后的面板承担应用、设备、文件与场景的组合。主要用户先聚焦：愿意自动隐藏 Dock、希望桌面安静、每天多次切应用与音频设备的 Mac 用户。

Apple 已在 Tahoe 增强控制中心定制与 Spotlight 操作能力。产品推断：单纯复制更多系统开关的差异化会持续减弱；把已有状态和应用能力串成可完成的任务，更值得投入。[Apple Tahoe 更新说明](https://support.apple.com/en-kw/122868)

## 代码与界面里实际发现的产品缺口

| 观察 | 证据 | 对用户的影响 | 建议 |
| --- | --- | --- | --- |
| 首页仍是四个大状态行，应用区在音量之后 | PopoverView.status、status-en.png | 启动/切换 app 的视觉优先级偏低 | 提供状态优先、应用优先两种预设；保留现有默认作为对照测试 |
| 首页只展示运行 app；固定 app 在设置→管理常用应用中 | runningApplications、settings、applications | 固定了但关闭后首页消失，无法形成 Dock 的稳定位置记忆 | 首页可选择固定+运行模式；固定位置稳定、去重，停止运行只移除运行标记 |
| 运行 app 按名称排序 | ApplicationShelf.refresh | 新 app 插入会推移图标，与肌肉记忆冲突 | 会话中保持槽位稳定；最近使用另列可选分组，不在指针下重新排序 |
| 固定入口来自现有列表，没有添加未运行 app 的选择器 | togglePin、应用页 | 用户需要先启动才能加入 | 增加“添加应用”，然后扩展受支持目录的已安装应用搜索 |
| 搜索只覆盖固定/运行列表 | applications、visible | 常见启动意图无法完成 | 全局快捷键 + 单一搜索框，结果注明“应用/动作/文件夹/设备” |
| 首页 app 图标没有应用页的上下文菜单 | runningApplications 对比 applicationRow | 需要进二级页才能固定、隐藏或 Finder 定位 | 统一交互与 VoiceOver 语义；精细菜单按能力显示 |
| 同样的状态行箭头有的打开内部页，有的跳系统设置 | statusRow | 行为预期不一致 | 内部展开用 ›，外部跳转用 ↗；外部名称明确“打开…设置” |
| 文件只是授权书签列表，统一 doc.on.doc 图标 | FileShortcutsView | 距离 Dock 文件栈体验尚远 | 文件类型图标、排序、授权目录内容、Quick Look、指定 app 打开 |
| 音量有事件监听，但设备列表更新仍靠进入/刷新等路径 | AudioChangeMonitor、soundOutputs | 已打开面板遇到拔插需要专项核实 | 默认输出、设备集合、连接消失的 UI 回读统一验收 |
| 引导仍以“四个图标，一个入口”为中心 | guide | 新用户不知道 Dock 能力 | 一分钟引导完成固定两个 app、设置入口快捷键、体验设备切换 |
| 二级页整体没有统一的可用屏幕高度约束 | PopoverView.body、各页 fixed height | 长翻译、权限提示、错误组合可能超出小屏 | 固定导航与底栏、内容滚动，按显示器可用高度约束；保留重开首页行为 |
| 验证以构建/模型/离屏预览为主，硬件写操作仍有待验项 | VALIDATION.md | “日常替代”可靠性未被充分证明 | 以任务成功验收：切音频、拔插、睡眠恢复、权限拒绝、外接屏/全屏 |

以上是源码与产品流程观察，不把未执行的实机行为标为已复现 bug。

## 大胆方向：可逐步试验，不一次性堆满首页

| 方向 | 具体体验 | 产品价值 | 实现判断与边界 | 优先级 |
| --- | --- | --- | --- | --- |
| 随处召唤 | 用户配置全局快捷键，在当前显示器或指针附近打开同一个面板；输入即可搜索 | 自动隐藏菜单栏、全屏和大屏也易达 | 快捷键冲突、焦点恢复、多显示器坐标需验证；默认仍是菜单栏锚点 | P1 |
| 常驻迷你 Dock | 把面板临时固定为浮动小面板，切应用时不关闭；再次点击返回菜单栏模式 | 长时间工作减少反复点开 | 独立窗口生命周期与空间归属；不承诺全局强制置顶/穿越所有全屏空间 | P2 原型 |
| 两行稳定应用架 | 固定 app + 运行 app 去重，拖拽排序；保留最多两行与末尾溢出入口 | 真正建立 Dock 使用习惯 | 用户现有“仅运行”默认可保留，以预设选项扩展，不偷偷改变行为 | P1 |
| 统一动作搜索 | 输入“AirPods”“音量 30”“下载”“Safari”找到设备、动作、目录、app | 一个入口贯穿现有模块 | 先用本地确定性匹配；模糊动作展示具体目标后执行，勿默认添加云端 AI | P1 |
| 文件投递口 | 拖文件到圆环，展开 app、文件夹与分享目标；悬停选目标、松手执行 | 连接 Dock 与文件系统的标志性交互 | 先支持授权文件交给 app 和系统分享；移动/复制需要额外写权限设计及冲突处理 | P2，适合先做原型 |
| Downloads 文件栈 | 用户授权下载目录后，按时间展示近期文件，预览、打开、分享 | 高频、容易理解的 Dock 增益 | 仅获授权目录，按需读取、限制数量；目录选取与权限恢复要顺畅 | P1/P2 |
| 一键工作场景 | “开会”：打开会议 app、选择输出/输入、展示检查结果；“写作”：打开文档/目录和指定快捷指令 | 让“融合”从图标延伸到操作 | 每一步显示成功/失败；先手动触发，不猜测会议；回滚只针对仍由场景持有且可回读的设置 | P2，核心差异化 |
| 可解释情境建议 | 插入显示器后提示桌面场景；热点连接时展示低数据模式状态与说明 | 状态直接产生下一步行动 | 只用已验证的本机信号；首先只建议，允许关闭；不自动改路由/网络偏好 | P2 |
| 会议前检查 | 一张卡核对音频输入/输出、电量、网络类型，并打开会议链接 | 汇集当前最成熟的状态能力 | 麦克风电平须单独权限/实现；系统录音隐私指示不仿制；不能把链路接通说成通话质量良好 | P2 |
| 按 app 找回窗口 | 点击 app 后选择窗口标题，再激活具体窗口；可选排列 | 补足“有进程，找不到窗口”的痛点 | 先验证辅助功能与沙箱；标题列表优先，缩略图涉及进一步屏幕权限。以成功聚焦而非按钮存在为验收 | P3 独立研究 |
| 手动工作空间 | 保存一组 app、目录、URL、动作，命名“项目 A” | 比泛用启动器更接近继续工作 | 第一版只保存明确入口；不宣称恢复未保存文档、任意 app 内部会话和所有窗口 | P2 |
| 用户配置动作 | 收藏几个已有 Shortcuts，为动作命名、选图标、固定到面板 | 低开发成本扩展长尾操作 | 官方 URL scheme 可运行已保存的快捷指令；不能把调用已发出显示成所有步骤已成功 | P2 |
| 同一圆环的三层信息 | 默认小圆环；悬停简明摘要；点击操作面板。可选较宽“圆环 + 一个数字”模式 | 兼顾美感与可读性 | 保留固定几何和异常优先级；遵循减少动态效果；不做持续呼吸/轮播数字 | P1 小试验 |
| 分享布局配方 | 导出应用顺序、模块显示和场景模板，分享“开发/设计/极简”预设 | 免费产品的自然传播入口 | 导出前预览；排除绝对路径、SSID、设备标识、书签、密码；快捷指令动作需逐项审核导入 | P3 |
| 我的 Mac 为什么这样 | 用户主动打开诊断，解释无软件音量、无网络名、权限、过期文件授权 | 减少支持成本，提高信任 | 解释可观察事实，勿推测根因；诊断导出先本地预览、默认去标识 | P1 |
| 轻量键鼠扩展 | 可选滚轮音量、键盘数字打开应用、左右键切模块、可见快捷键提示 | 高频操作更快 | 滚轮默认关闭防误触；焦点与输入法不冲突；不占用系统习惯快捷键 | P2 |

Shortcuts 依据：[Apple 官方 URL scheme](https://support.apple.com/en-euro/guide/shortcuts-mac/apd624386f42/mac)。文件拖到 app 等用户预期依据：[Apple Dock 指南](https://support.apple.com/guide/mac-help/open-apps-from-the-dock-mh35859/mac)。以上优先级为产品判断，非可用 API 全量认证。

## 建议的信息架构

固定的菜单栏圆环 → 紧凑状态摘要 → 稳定两行应用 → 四个可配置快捷动作 → 可选搜索。

- 状态优先预设保留当前信息顺序；应用优先预设将四行详情收进紧凑设备区，释放首屏给应用。
- 常态首页展示可执行内容；出现异常时，在固定位置给出一条可理解的原因与动作。
- 声音/网络/蓝牙仍是内部详情；长尾设置集中到系统页，外部跳转统一图标。
- 配置页集中在独立设置窗口的可行性值得验证，让日常面板保持短。当前版本先保留原设置页。
- 重开回首页保持既有要求。浮动固定模式是独立模式，不能重新引入关闭后留在二级页的问题。
- 全部新交互同步五语、键盘、VoiceOver、增大对比度、减少动态效果支持。

## 克制清单与渠道策略

优先后置：完整剪贴板历史、天气/股票信息流、硬件监控大仪表盘、万能插件市场、通用 AI 聊天、自动清理内存。这些会带来持续维护与权限负担，且不直接完成“状态→操作→继续工作”的主路径。简单月历/计时器可以作为未来可选动作，不占默认首页。

暂不承诺：全局第三方通知/徽章复制、系统隐私指示复制、任意 Dock 动态菜单、全系统窗口与 Spaces 等价控制、完全隐藏所有系统入口。当前沙箱 app 不能用 NSRunningApplication.terminate 退出其他 app，是 Apple 明示限制。[官方文档](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate%28%29)

近期继续共用双渠道核心，免费不变；只有窗口增强验证出清晰用户价值且确实需要不同权限/打包时，才决定是否维护 GitHub 增强版。不提前把“窗口功能需辅助功能”误写成“必然不能上架”。共享本地数据格式也需要迁移测试。

## 推荐推进顺序与停止条件

1. **稳定日用基础**：补齐当前硬件写操作、弹窗、权限、长文本、睡眠/多显示器验收；让已安装版本、源码、公开 release 的能力描述一致。完成现有发布阻塞与 GitHub 升级体验。
2. **下一轮主线**：可配置召唤快捷键、未运行 app 添加/搜索、首页稳定应用架、首页右键操作、明确内部/外部入口。用同一套动作模型服务鼠标与搜索，避免两套行为。
3. **差异化原型，二选一先测**：文件投递口或一键工作场景。用户测试胜出的先产品化，不同时扩展十个模块。
4. **窗口专项**：先标题列表与准确聚焦，再决定是否值得加入预览和排列；权限拒绝时核心功能继续工作。
5. **配置分享与传播**：在核心路径可靠后做布局模板、五语演示与清晰兼容性矩阵。

建议验收目标（待实测，并非当前成绩）：

- 菜单栏点击与全局快捷键均可在两次操作内激活固定 app；从未运行状态也能完成。
- 面板打开期间任意 app 启动/退出，不让正在点击的目标换位。
- 给 5–8 位用户完成切 app、切音频、打开最近下载、找回窗口四类任务；记录时间、失败、回到系统入口的原因，并与原生流程比较。
- 场景不以“请求发出”当成功，设备消失、权限不足、部分失败都可解释。
- 首次使用 60 秒内完成两项有效操作；不要求先授权所有权限。
- 性能先建本机空闲/开关面板/设备事件基线，再定回归预算；禁止以常驻动画和持续扫描换取表面活跃。
- 一周后主要看用户是否自愿保留 Dock 自动隐藏，以及哪些任务仍必须回来找 Dock；小样本访谈与自愿本地记录即可，无需默认上传行为日志。
